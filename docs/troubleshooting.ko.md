# Polydeukes 문제 해결

[English](./troubleshooting.md) · **한국어**

정책을 바꾸기 전에 어느 단계에서 실패했는지 확인하세요. 세션이 복구 명령까지 차단한다면
본인의 터미널에서 실행합니다. `pdks docs`는 동봉 문서가 온전하면 프로젝트 설정이나
판정 관련 패키지가 없어도 사용할 수 있습니다.

<a id="no-config"></a>
## 설정 파일이 없을 때

프로젝트 루트 바로 아래에 `polydeukes.config.yaml`, `polydeukes.config.yml`,
`polydeukes.config.json` 중 하나도 없으면 설정이 필요한 명령은 종료 코드 2를 반환합니다.
Git에서 원래 파일을 복원하세요. 새 프로젝트라면 `pdks init`, `pdks adapter claude-code init`,
`pdks adapter grok init`, `pdks adapter codex init`로 만들 수 있습니다. 이후 `pdks explain`을 실행합니다.
설정이 없다고 기본 정책으로 대신 실행하지는 않습니다.

<a id="multiple-config"></a>
## 설정 파일이 여러 개일 때

오류 메시지에 중복된 파일명이 나옵니다. 필요한 내용을 합친 뒤 허용되는 파일명 하나만
남기세요. 로더는 어느 파일을 사용할지 임의로 선택하지 않습니다. 정리한 뒤
`pdks explain`을 다시 실행합니다.

<a id="invalid-config"></a>
## 설정 오류

구문이나 스키마 오류가 있으면 종료 코드 2와 함께 파일명을 알립니다. 스키마 오류는 문제가
있는 필드도 알려 줍니다. 잘못된 YAML, 사용자 정의 태그, 알 수 없는 필드를 고치세요. YAML
태그는 파서가 실행할 수 없더라도 거부합니다. 설정은 실행할 코드가 아니라 데이터이기 때문입니다.

`protectedPath:`나 `adaptors:` 같은 오타는 거부합니다. 다만 어댑터 이름에는 확장 가능성을
남겨 두었습니다. 아무도 구현하지 않은 네임스페이스도 설정으로 읽히지만 읽는 쪽이 없습니다.
수정한 뒤 `pdks explain`에서 실제 등록 내용을 확인하세요.

세션 안에서는 수정 자체가 막히지 않습니다. 설정이 로드되지 않는 동안 모든 호출은 차단되지만
하나는 예외입니다. 대상이 설정 파일 하나뿐이고, 시작 텍스트가 디스크에 있는 파일 그대로이며,
그 결과가 로드되는 Edit 또는 Write는 종료 코드 0으로 통과하며, `covenant-check` 라벨의
`advised` 행 하나를 고쳐진 설정 자신의 `telemetry.logPath`에 남기고 stderr에 고친 오류를
알립니다. 이 통과는 `--enforce` 기본 자세를 읽지 않습니다. 세션 훅은 항상 `--enforce block`으로
실행되므로, 그 아래에서 차단되는 수정은 어디에서도 실행되지 못하기 때문입니다. 결과가 여전히
로드되지 않는 수정은 다른 호출처럼 차단되고, 설정 파일과 다른 파일을 함께 건드리는 호출이나
디스크의 바이트에서 시작하지 않는 증거를 실은 호출도 차단됩니다. 변경 집합 표면에는 이런 경로가
없습니다. 설정을 고치는 커밋은 오류를 볼 수 있는 터미널에서 사람이 만드는 커밋이기 때문입니다.

<a id="grok-witness"></a>
## Grok 증인

훅을 아직 읽지 않은 문제와 증인(witness) 밸브를 사용할 수 없는 문제는 구별해야 합니다.

- `pdks adapter grok init` 실행 뒤 Hooks 탭을 다시 불러오거나 새 세션을 시작하세요. 실제 도구를
  호출하고 텔레메트리를 확인합니다. 설치기가 성공했다고 해서 열린 세션에 훅이 적용됐다는
  뜻은 아닙니다.
- Grok의 ACP 대화 기록에는 현재 세션 증인 밸브가 요구하는 Claude 형식의 인간 메시지가
  없습니다. 다시 불러와도 이 기능이 생기지는 않습니다. 복구가 필요하면 Grok에 Claude용
  증인 토큰을 보내려 하지 말고 본인의 터미널에서 작업하세요.

변경 집합 표면에는 증인 프롬프트가 없으며 차단된 Grok 도구 호출을 허용하지 않습니다.

<a id="codex-witness"></a>
## Codex 증인

`/hooks`에서 등록을 승인한 뒤 실제 호출과 telemetry를 확인하세요. 신뢰는 정의의 hash에 연결되므로 경로가 바뀌면 재승인이 필요할 수 있습니다. 현재
`UserPromptSubmit`은 사람 출처를 증명하지 않으므로 토큰을 보내도 증인(witness) 밸브를 열지 않습니다. `PostToolUse` 증거는 세션·하위 에이전트별로
분리하고 `SessionEnd`에 정리합니다. 불안정한 대화 기록 파일은 읽지 않습니다. 필요한 보호 변경은 사용자 터미널에서 수행하세요.

<a id="config-fault"></a>
## 선언을 판정으로 구성하지 못할 때

어떤 선언을 판정할 수 있는 형태로 컴파일하지 못하면 설정 전체가 오류가 됩니다. 등록되지 않은
추출 단계, 그 단계가 받지 않는 인수나 형식이 잘못된 인수, `source`나 결합자로 시작하지 않는
파이프라인, 단일 추출 결과가 필요한 자리에 쓴 쌍 추출 결과가 여기에 해당합니다. 로드는
[설정 오류](#invalid-config)에서 설명한 대로 실패하고, 메시지가 항목과 파이프라인 또는 relate
항목, 그리고 사유를 알립니다. 지목된 선언을 고친 뒤 `pdks explain`을 다시 실행하세요.

<a id="judge-cannot-be-loaded"></a>
## 판정기를 실행할 수 없음

등록된 절대 경로의 `pdks`가 존재하고 실행 가능한지 확인하세요. 실행 파일이나 프로젝트를 옮겼다면 사용자 터미널에서 새 위치의 `pdks adapter <host>
init`을 실행하고 호스트 신뢰를 다시 확인합니다. 단일 실행 파일에는 판정기와 세 어댑터가 들어 있습니다. 소스 체크아웃의 npm 설치를 사용한다면 의존성 설치와 전체
workspace build를 복구해야 합니다.

등록된 실행 파일이 시작되지 못하는 동안 세 호스트는 파일을 바꾸거나 셸을 실행하는 도구 호출을 모두 차단하고, 세션 자체는 계속됩니다. prompt는 그대로
제출되고 읽기 도구도 실행되므로, 거부 사유를 읽고 경로를 고칠 수 있습니다. 다른 기기에서 커밋한 등록은 그 기기의 경로를 가리키므로, 자신의 기기에서 init을 실행하세요.

훅이 시작되기 전의 실패는 telemetry를 남기지 못할 수 있습니다. 시작된 훅이 잘못된 입력을 받으면 공통 판정기에 `--input-failure`를 보내 원인 한 번과
`blocked covenant-check` 행 한 건을 기록합니다. 입력 EOF와 자식 통신의 내부 기한은 각각 10초입니다. 호스트 자체의 신뢰·비활성화·시간 초과 처리는
별개이므로 실제 거부와 로그를 함께 확인하세요.

<a id="reading-verdict"></a>
## 판정 결과 읽기

| 기록 | 의미 |
|---|---|
| `passed` | 관측한 입력을 판정했으며 약속(covenant)을 지켰습니다. |
| `blocked` | 위반 때문에 작업을 멈췄습니다. |
| `witnessed` | 차단 결과가 나왔지만 증인 밸브를 통해 작업을 허용했습니다. |
| `advised` | 위반을 기록하되 작업을 멈추지 않았습니다. 두 표면 모두에서 나올 수 있습니다. |
| `skipped` | 적용 범위가 일치한 등록을 판정할 수 없었습니다. 정상 판정이 아닙니다. |
| `unattributed` | 기준 상태와 비교해 판정으로 설명되지 않는 보호 대상의 변경을 발견했거나, 유효한 기준 상태를 읽지 못했습니다. 판정 결과가 아니라 관측 기록입니다. |

판정은 기본적으로 `.polydeukes/roi.log`에 추가됩니다. `telemetry.logPath`로 위치를 바꿀 수
있습니다. 로그 쓰기에 실패하더라도 판정 결과는 바뀌지 않습니다. 종료 코드 0은 작업을
계속해도 된다는 뜻이지 모든 규율을 지켰다는 뜻은 아닙니다.

<a id="opening-a-blocked-call"></a>
## 차단된 호출을 증언으로 허용하기

지원되는 Claude Code 세션에서 설정된 증인 토큰을 인간 메시지의 첫 줄에 단독으로 입력한 뒤,
유효 시간 안에 다시 시도합니다. 보호 대상을 의도적으로 편집하기 전에 입력해도 됩니다.
먼저 한 번 차단돼야 하는 것은 아닙니다. 토큰은 비밀이 아니며, 밸브는 사람이 직접 입력했는지
확인하고 차단 판정에만 적용됩니다. 증언으로 허용한 호출은 `witnessed` 행을 새로 남깁니다.
앞서 기록한 `blocked` 행을 고치는 것이 아닙니다.

밸브가 열 수 있었던 차단을 열지 않았다면, 차단 메시지의 마지막 줄이 그 이유를 알려 줍니다.
`no witness is configured`는 `witness: { token, ttlMinutes }`를 추가할 설정 파일을 알려 주며,
추가하기 전까지는 어떤 메시지로도 차단을 허용할 수 없습니다. `a person can open this for <n>
minutes`는 밸브가 설정돼 있지만 유효 시간 안에 토큰 메시지가 없다는 뜻입니다. 여기에
`the last witness expired at <time>`이 붙으면 토큰을 보낸 적은 있지만 유효 시간이 지났으므로
다시 보내야 합니다. 이 줄에는 토큰이 들어가지 않습니다.

모듈 누락처럼 판정기를 조립하지 못하게 하는 오류는 증인으로 해결할 수 없습니다.

<a id="blocked-commit"></a>
## 커밋이 차단됐을 때

변경 집합 표면은 사람에게 묻지 않습니다. 기본값에서는 모든 판정에 종료 코드 0을 내고 위반을
`advised`로 기록합니다. 종료 코드 2는 검사를 `--enforce block`으로 실행했을 때(보호 경로나
`enforce: block` 항목의 위반) 또는 판정 자체가 불가능할 때만 냅니다. 커밋을 멈출지는 훅
배선이 정합니다. 종료 코드를 따르는 훅은 커밋을 멈추고, 무시하는 훅은 멈추지 않습니다. Git은
커밋 실패를 다른 0이 아닌 코드로 알릴 수도 있습니다.

일반 규율 항목은 자신이 `enforce: block`을 적고 검사가 `--enforce block`으로 실행될 때만
작업을 멈춥니다. 설정에는 기본값 `advise`인 항목을 승격하는 것이 없습니다. 수준 변경은
정책을 바꾸는 결정이지 필수 복구 절차가 아닙니다. 판정된 위반을 통과시키려면 설정이 아니라
훅 명령에서 `--enforce block`을 빼세요. 행은 그대로 남습니다.

<a id="skipped-rows-on-the-change-set-surface"></a>
## 변경 집합 표면의 미판정 기록

변경 집합 표면은 `disciplines`와 `changeSetDisciplines`를 컴파일합니다.
대화 기록이나 명령줄을 읽는 항목은 `sessionDisciplines`에 속하며 diff 판정에는 포함되지
않습니다. 이런 항목을 공용 목록이나 변경 집합 목록에 넣으면 설정 오류가 발생합니다.

변경 집합 항목이 읽는 소스가 없고 `supply` 정책이 `pass`이면 `supply-pass`를 기록합니다.
`pdks explain`과 로그의 사유를 확인하세요. 미판정은 규율을 지켰다는 증거가 아닙니다.

세션 표면에서는 호스트가 대화 기록을 공급하지 않을 때
`supply: { session: 'pass' }`로 건너뛸 수 있습니다.
[규율 목록 셋](./reference/configuration/index.ko.md#three-lists)을 참고하세요.

<a id="local-state"></a>
## 다른 컴퓨터로 프로젝트를 옮길 때

텔레메트리와 `.polydeukes/baseline.json`은 로컬 상태이며 Git이 옮겨 주는 판정 이력이
아닙니다. 이 파일 없이 저장소를 복제해도 과거 판정이 복원되지는 않습니다. memory 조회 로그
`.polydeukes/memory-log.jsonl`도 로컬 상태입니다. memory 색인은 문서에서 다시 만들 수 있지만,
조회가 무엇을 돌려줬는지 적은 로그는 다시 만들 수 없습니다. 세션 훅은 기준
상태가 없거나 유효하지 않으면 이를 기록하고 다음 비교에 쓸 기준을 만듭니다. 과거 변경을
판정했다는 증거가 생기는 것은 아닙니다. 필요한 로그는 따로 보관해 옮기세요.
`telemetry.logPath`를 바꿨다면 모든 기록이 `.polydeukes/`에 있다고 가정해서는 안 됩니다.
