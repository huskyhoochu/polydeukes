# Building Polydeukes in Public #7 — Twenty-five documents, one offline index, and the reader we have not met yet

**English** · [한국어](./2026-09-v0.6.1-docs-and-search.ko.md)

> *v0.6.1 · the public documentation was rewritten from forty-six files with no declared
> roles into twenty-five catalogued documents in two languages, sixteen legacy files were
> deleted rather than redirected, and `pdks docs` searches that catalogue from the installed
> package with no network and no judge. This post is a documentation milestone's report: what
> the rewrite kept, what a fact-check corrected, what one measurement of someone else's
> memory tool says about our own design, and the one reader test we deferred.*

Post #6 said post #7 would belong to the entry-point reshape. Between the two, the owner
inserted a documentation milestone ahead of it — the docs described a product three
refoundations old, and nobody outside the repository could have installed from them. v0.6.1
closed on 2026-09-06 with one implementation PR. This is its account, and the reshape moves
to post #8.

## What shipped: a catalogue with roles, and nothing at the old addresses

The starting tree had thirty-four markdown files under `docs/` and twelve READMEs, written
across five milestones, with no statement of which file was current. The rewrite began by
classifying every one of them in a disposition table — current document, old address, new,
README — and the classification decided what happened to each: current documents were
rewritten against the live code, old addresses were first kept as redirects and then, in one
commit, **deleted outright** with the facts they still held moved into the current guides.
The tree ends at twenty-five documents, each an English–Korean pair, listed in
`docs/catalog.json` with an id, a category, an order, and a `bundled` flag. Seventeen of the
twenty-five ship inside the package. The catalogue and the tree agree one-to-one, and a
check script verifies the bilingual pairing and every local link and anchor across all
sixty-four files on each CI run.

The rule that governed the rewrite was that a document has one role. A tutorial does not
explain the configuration schema; the configuration reference does not narrate history; the
twelve build-in-public posts stay as historical accounts and are marked as such in the
catalogue's summary line, so that a search hit on one of them tells the reader it is not a
usage reference.

## Search that survives the judge being removed

`pdks docs search`, `docs show --section`, and `docs install` read the bundled catalogue from
the installed package. The acceptance test was not that search returns results but that it
returns the *same* results offline: the tarball was installed into an isolated directory, the
network was cut with `sandbox-exec` (a `curl` exit 7 proved the cut), there was no config
file, and the four query shapes — English search, Korean search, section show, install —
produced byte-identical output to the online baseline. Then the judge package was removed
from that install: `pdks explain` failed with exit 2 as it should, and the four documentation
commands still matched the baseline. Documentation works on a machine where judgment cannot.

Twelve fixed queries — six in each language, chosen from the questions the tutorials answer —
are the regression fixture. Eleven land the expected document and section first; one Korean
query lands second, behind a troubleshooting section that is also a correct answer, and the
contract is top-three, so it passes. Each query runs in a fresh process in 30 to 49
milliseconds against a one-second budget. The bundled documentation is 392 KiB uncompressed
against a 5 MiB budget. Turbo declares `docs/**` as a build input, and the gate verified the
consequence: appending one sentence to the troubleshooting guide invalidated the umbrella's
build cache and made the installed search return that sentence; reverting it restored the
cache hit and the zero-result search.

## What the fact-check corrected

The Korean mirrors were polished for style, and a diff review of every polish caught the
places where a smoother sentence had changed a fact. The polish is recorded as a review file
so that the next editor can see what was and was not touched. Four factual candidates were
then judged against the code and the archived PRDs, and three were corrected — as editor's
notes, never by rewriting the historical sentence:

- Post #6 said every one of the twenty-four judged entries "and one draft" had left telemetry
  rows. A `draft: true` entry is registered and read but never judged, so it writes no row.
  The note stands in post #6 in both languages.
- Post #4 reported thirteen review findings as nine, three, and two. The sum is fourteen, and
  the archived PRD's own summary is nine, three, one. The numbers were left as written and
  the discrepancy is noted.
- The configuration reference's first sentence on the commit adapter's `block` setting read
  as if it promoted every entry. It promoted only the adapter level; ordinary entries stayed
  advise. The sentence gained its qualifier. (The setting itself was removed one ticket later
  by the reshape — see post #8.)

The fourth candidate — post #6's "304 = 284 + 18" — was correct as an abbreviation: the
journal's table has two more assembly fail-closed rows, and 284 + 2 + 18 is 304. No change.
The README table also gained *(planned)* markers on the ledger, memory, and verify packages,
which the previous wording presented as if they shipped.

## A measurement we did not have to pay for

The roadmap set this post one judgment: whether a six-week review of cognee, the local
memory index this project's wiki has been using since July, belongs beside the row-first
argument in *Why Polydeukes*. The review counted fifty-three recall queries — thirty-two
accurate, fifteen partial — and then measured the index itself. The index held 142 documents
more than the wiki (36% of it was files that had been deleted or renamed, since deletion does
not propagate), and it had grown to 147 times the size of the source text. Every defect
traced to one root: storage separated from the source, synchronised in one direction.

That is the row-first premise — the extraction cost is paid by whoever writes, and the store
is never the source — demonstrated at someone else's expense. The judgment: it belongs in
this post as a measurement, and *not yet* in the design document. *Why Polydeukes* §2 makes a
claim about a store we have not built; attaching another tool's failure to it would present
a prediction as a result. The number goes into the design document when our own store has
been measured the same way.

## Release footnote

The implementation PR carried two `feat:` commits, so release-please's default calculation
would have produced 0.7.0 for a documentation milestone. The squash commit carried a
`Release-As: 0.6.1` footer instead, the release PR bumped the root and all five packages to
0.6.1 in lockstep, and the tag, the Forgejo release, the mirror to GitHub, and the npm
publish followed the chain post #6 described. The full suite at the merge commit was 2,587
tests across five packages, green.

Two owner decisions closed the milestone. The "representative paragraph" review — a
first-time reader checking the one paragraph each document opens with — was absorbed into
ongoing maintenance rather than held as a gate. And the **reader six-task test** — a reviewer
who has never seen the project performs install, discipline authoring, error recovery, option
lookup, package call, and search-result lookup from the documentation alone, once in each
language, recording where they got stuck — was moved out of this milestone's exit criteria
and into the v0.7.0 gate. The reasoning is that the reshape changes the install shape, so a
reader test against the pre-reshape docs would measure a layout about to disappear.

Division of labour, for the record: implementation, the disposition table, and the English
fact-check were done by GPT-6 Astra and Grok; the Korean polish by Astra; verification runs,
fact-check judgments, and the close-out by Claude. The only human approvals were the two
decisions above and the merge.
