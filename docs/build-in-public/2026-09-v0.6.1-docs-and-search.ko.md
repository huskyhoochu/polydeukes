# Polydeukes를 공개적으로 만들기 #7 — 문서 스물다섯, 오프라인 색인 하나, 그리고 아직 만나지 못한 독자

[English](./2026-09-v0.6.1-docs-and-search.md) · **한국어**

> *v0.6.1 · 역할 표시가 없던 마흔여섯 파일의 공개 문서를 두 언어의 카탈로그 문서
> 스물다섯으로 다시 썼고, 구문서 열여섯은 리다이렉트 대신 삭제했으며, `pdks docs`가 설치된
> 패키지 안의 카탈로그를 네트워크도 판정기도 없이 검색한다. 이 편은 문서 마일스톤의
> 보고다 — 재작성이 무엇을 보존했는지, 사실 확인이 무엇을 정정했는지, 남의 기억 도구를
> 잰 측정 하나가 우리 설계에 무엇을 말하는지, 그리고 미룬 독자 시험 하나.*

포스트 #6은 #7이 진입점 재편의 몫이라고 적었다. 그 사이에 소유자가 문서 마일스톤을 앞에 끼워
넣었다 — 문서가 세 번의 재정초 전 제품을 설명하고 있어서, 저장소 밖의 누구도 그 문서로
설치할 수 없었기 때문이다. v0.6.1은 2026-09-06에 구현 PR 하나로 닫혔다. 이 편이 그 기록이고,
재편은 #8로 옮긴다.

## 출하된 것 — 역할이 있는 카탈로그, 옛 주소에는 아무것도 없음

시작 트리에는 `docs/` 아래 마크다운 서른넷과 README 열둘이 있었다. 다섯 마일스톤에 걸쳐
쓰였고 어느 파일이 현행인지 어디에도 적혀 있지 않았다. 재작성은 그 전부를 처리표 하나에
분류하는 것으로 시작했다 — 현행 문서, 이전 주소, 신규, README — 그리고 그 분류가 각 파일의
운명을 정했다. 현행 문서는 라이브 코드에 맞춰 다시 썼고, 이전 주소는 처음에는
리다이렉트로 두었다가 한 커밋에서 **통째로 삭제**했으며, 거기 남아 있던 사실은 현행
안내로 옮겼다. 트리는 문서 스물다섯에서 끝난다. 각각 영한 한 쌍이고, `docs/catalog.json`에
id · 분류 · 순서 · `bundled` 플래그로 등재된다. 스물다섯 중 열일곱이 패키지 안에 실린다.
카탈로그와 트리는 1:1로 일치하고, 검사 스크립트가 CI마다 예순네 파일 전체의 영한 쌍과
로컬 링크 · 앵커를 검증한다.

재작성을 지배한 규칙은 문서 하나에 역할 하나다. 튜토리얼은 설정 스키마를 설명하지 않고,
설정 참조는 이력을 서술하지 않으며, build-in-public 열두 편은 당시의 기록으로 남고
카탈로그의 요약 줄에 그렇게 표시된다 — 검색이 그중 하나를 맞히면 독자는 그것이 사용법
참조가 아니라는 것을 먼저 읽는다.

## 판정기를 치워도 살아남는 검색

`pdks docs search` · `docs show --section` · `docs install`은 설치된 패키지에 번들된
카탈로그를 읽는다. 수용 기준은 검색이 결과를 낸다가 아니라 오프라인에서 *같은* 결과를
낸다였다. tarball을 격리 디렉터리에 설치하고, `sandbox-exec`로 네트워크를 끊고(`curl` exit
7이 끊김을 증명), 설정 파일 없이, 네 가지 질의 형태 — 영어 검색 · 한국어 검색 · 절 표시 ·
설치 — 를 돌려 온라인 기준 출력과 바이트 동일한 결과를 얻었다. 그다음 그 설치본에서 판정기
패키지를 치웠다. `pdks explain`은 마땅히 exit 2로 실패했고, 문서 명령 넷은 여전히 기준과
같았다. 판정이 불가능한 기계에서도 문서는 동작한다.

고정 질의 열둘 — 언어별 여섯, 튜토리얼이 답하는 질문에서 골랐다 — 이 회귀 픽스처다.
열한 건이 기대 문서와 절을 1위로 맞히고, 한국어 질의 하나가 2위다(1위는 역시 정답인
문제 해결 절이고, 계약은 상위 3위 안이라 충족). 각 질의는 새 프로세스에서 30~49밀리초에
끝나고 예산은 1초다. 번들 문서는 비압축 392 KiB이고 예산은 5 MiB다. turbo는 `docs/**`를
빌드 입력으로 선언하며 관문이 그 결과를 검증했다. 문제 해결 안내에 문장 하나를 덧붙이자
우산의 빌드 캐시가 무효화되고 설치본 검색이 그 문장을 돌려주었으며, 되돌리자 캐시 적중과
검색 0건으로 돌아왔다.

## 사실 확인이 정정한 것

한국어 미러를 문체 층위에서 윤문했고, 윤문 하나하나를 diff로 검토해 매끄러워진 문장이
사실을 바꾼 자리를 잡아냈다. 윤문은 검토 파일로 남겨 다음 편집자가 무엇을 손댔고 무엇을
손대지 않았는지 볼 수 있다. 사실 후보 넷을 코드와 보관 PRD에 대조해 셋을 정정했다 —
편집자 주로, 당시의 문장을 고쳐 쓰지는 않고.

- #6은 판정 항목 스물넷 "과 초안 하나" 전부가 텔레메트리 행을 남겼다고 적었다. `draft:
  true` 항목은 등록되고 읽히지만 판정되지 않으므로 행을 쓰지 않는다. 주는 #6 영한에 있다.
- #4는 리뷰 소견 13건을 9 · 3 · 2로 적었다. 합은 14이고 보관 PRD의 요약은 9 · 3 · 1이다.
  수치는 적힌 대로 두고 불일치를 주로 남겼다.
- 설정 참조에서 커밋 어댑터 `block` 설정의 첫 문장은 모든 항목을 승격하는 것처럼 읽혔다.
  승격되는 것은 어댑터 수준뿐이고 일반 항목은 advise로 남는다. 문장에 한정어를 붙였다.
  (그 설정 자체는 한 티켓 뒤 재편이 지웠다 — #8을 보라.)

넷째 후보 — #6의 "304 = 284 + 18" — 는 생략형으로 맞았다. 저널 표에는 조립 fail-closed
2행이 더 있어 284 + 2 + 18 = 304다. 수정 없음. README 표는 ledger · memory · verify
패키지에 *(계획)* 표시를 얻었다. 이전 문구는 그것들이 출하된 것처럼 보였다.

## 우리가 값을 치르지 않은 측정 하나

로드맵은 이 편에 판정 하나를 맡겼다 — 이 프로젝트의 위키가 7월부터 써 온 로컬 기억
색인 cognee의 6주 실사용 리뷰를 *Why Polydeukes*의 row-first 논거 옆에 붙일 것인가.
리뷰는 회상 질의 쉰셋을 셌고 — 정확 서른둘, 부분 열다섯 — 그다음 색인 실물을 쟀다.
색인은 위키보다 문서 142개가 많았고(36%가 삭제되거나 이름이 바뀐 파일이었다 — 삭제가
전파되지 않는다), 원문의 147배로 부풀어 있었다. 결함은 전부 한 뿌리로 돌아갔다. 저장이
원본과 분리돼 있고 동기화가 한 방향이다.

그것이 row-first의 전제 — 추출 비용은 쓰는 사람이 내고, 저장소는 결코 원본이 아니다 —
를 남의 비용으로 보여 준 자리다. 판정은 이렇다. 이 편에는 측정으로 싣고, 설계 문서에는
*아직* 싣지 않는다. *Why Polydeukes* §2는 우리가 아직 만들지 않은 저장소에 대한 주장이고,
거기에 남의 도구의 실패를 붙이면 예측을 결과처럼 내놓는 것이 된다. 그 수치는 우리 저장소를
같은 방식으로 쟀을 때 설계 문서로 들어간다.

## 릴리스 각주

구현 PR에 `feat:` 커밋이 둘 있어서 release-please의 기본 계산은 문서 마일스톤에 0.7.0을
냈을 것이다. squash 커밋에 `Release-As: 0.6.1` 푸터를 실었고, 릴리스 PR이 루트와 다섯
패키지를 0.6.1로 함께 올렸으며, 태그 · Forgejo Release · GitHub 미러 · npm 출판이 #6이 적은
사슬을 따랐다. 병합 커밋의 전체 스위트는 다섯 패키지 2,587건, 초록이다.

소유자 결정 둘이 마일스톤을 닫았다. "대표 문단" 검토 — 처음 읽는 독자가 문서마다 첫
문단을 확인하는 것 — 는 관문으로 붙들지 않고 장기 수정에 흡수했다. 그리고 **독자
6과제** — 프로젝트를 본 적 없는 검토자가 문서만으로 설치 · 규율 작성 · 오류 복구 · 옵션
조회 · 패키지 호출 · 검색 결과 조회를 언어별 1회씩 수행하고 막힌 자리를 적는 것 — 는 이
마일스톤의 완료 조건에서 v0.7.0 관문으로 옮겼다. 재편이 설치 형상을 바꾸므로, 재편 전
문서로 독자를 재면 곧 사라질 형상을 재는 셈이라는 이유다.

기록을 위한 분담. 구현 · 처리표 · 영어 사실 확인은 GPT-6 Astra와 Grok가, 한국어 윤문은
Astra가, 검증 실행 · 사실 확인 판정 · 마감은 Claude가 했다. 사람의 승인은 위 결정 둘과
병합뿐이다.
