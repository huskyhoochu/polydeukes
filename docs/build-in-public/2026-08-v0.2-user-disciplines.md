# Building Polydeukes in Public #2 — The number we promised to report was measuring the wrong thing

**English** · [한국어](./2026-08-v0.2-user-disciplines.ko.md)

> *v0.2 · disciplines become user-declared data, the witness valve moves behind the verdict, and
> the number post #1 promised to report turns out to have been an artifact of its own
> measurement device.*

Post #1 ended with two commitments. The ledger claim would come due at its own milestone — the
editor's note there already records the re-cut, and under the numbering that stands today the
ledger sits at v0.7 — and post #2 would claim exactly one thing about the enforcement layer's
own cost: whether `bypassed = 552` collapsed. The result of that second commitment was not what we
predicted. The number collapsed,
but it had never measured what three rounds of our own journal said it measured.

## What v0.2 actually shipped

v0.1 was the enforcement core protecting its own substrate. v0.2 is the release line where
**users declare disciplines** — the milestone was re-cut to put that before the ledger, and
this post reports against the re-cut plan, as promised.

- **Disciplines are data.** A `disciplines:` entry in the config file — an `id`, a `why`, and
  exactly one predicate — becomes enforcement, per-discipline telemetry, and a labeled block,
  with zero plumbing code. Four built-in families ship: path (`immutable`), content delta
  (`forbid`, with debt amnesty — only what an edit *adds* is judged), command
  (`forbidCommand`, which catches gate-disarming commands that mention no protected path at
  all), and context (`requirePrecedent`, which judges the *session history* in front of a
  change rather than the change itself — evidence means an execution that succeeded, not a
  mention).
- **The witness valve moved behind the verdict.** v0.1's escape hatch was session-global and
  sat *in front of* judgment. The TTL witness replaces it: a human types the token so it
  stands alone on a message's first line, the window holds for `ttlMinutes`, and — the part
  that matters — **the valve is consulted only after a verdict blocked.** A call that would
  have passed anyway never touches it. Provenance is the defence: only human-authored
  messages count, so the agent cannot open the valve for itself even knowing the token.
- **A second surface, and a second adapter.** `pdks covenant check` judges the staged diff at
  commit time through the same judges the session hook spawns. The git adapter fills the same
  agent-neutral evidence IR as the Claude Code adapter — and adding it changed **zero lines
  of core**, which is the practical proof of IR neutrality we claimed to be designing for.
- **Live validation, twelve scenarios.** After the discipline library landed, a scripted
  session ran 8 block-expected and 4 pass-expected scenarios: 8/8 blocked under their own
  discipline labels, 4/4 passed, zero false positives. One edit that broke two promises left
  five telemetry rows — every matching discipline judges and records, no short-circuit — which
  is what makes per-discipline ROI a computable number instead of a slogan.

## The 552 report — the metric was the artifact

The following sequence identifies what each number measures.

Post #1 reported `bypassed = 552` over the v0.1 milestone ledger and called it the cost of a
session-global valve. Rounds 2 through 4 of our dogfooding journal tracked that ratio as *the*
friction metric — at its peak the cumulative log read 28% `bypassed`. Then the v0.2 gate
recount asked a question nobody had asked: **what does the denominator count?**

The answer: the old valve sat in front of the verdict, so the log counted **every call that
mentioned a protected path inside an armed window** — the overwhelming majority being calls
that would have passed with no valve at all. The metric measured the size of the armed window,
not the use of the valve. Three journal rounds drew conclusions from a number that was an
artifact of its own measurement device.

Two changes, made for independent reasons, let us re-measure the axis properly:

| Date (daily rows) | `bypassed` | `witnessed` | What changed |
|---|---|---|---|
| 07-25 | 1,019 | — | before the protection-surface narrowing |
| 07-26 | 38 | — | narrowing day: sources moved to the commit surface's own list |
| 07-28 | 130 | 37 | valve moved behind the verdict (mixed day) |
| 07-29 | **0** | 20 | first clean day after the move |

After the valve moved behind the verdict, the same axis reads **0.65%** (20 of 3,053 judged
calls that day), and every one of the cumulative 57 `witnessed` rows names a real block a
human opened in person — 54 of them on the self-mod covenant, exactly where a human editing
the judging chain should appear. Narrowing the protection surface also had a measurable effect:
1,019
to 38 in one day, a fortieth. Package sources moved to the commit surface's additive
list, allowing session edits while keeping the *commit* as the judged checkpoint. The
measured basis for that call: the old list had opened the valve 2,414 times against 14 blocks
that user disciplines actually produced.

All the numbers above share a limitation: `passed` is an upper bound and `blocked` a lower one.
That limitation also applies to future reports. An agent that predicts a block
reshapes the call before making it, and the reshaped call passes legitimately with no record
that anything was avoided.

## What the gate overturned, and what it refused to promise

The v0.2 gate re-verified the milestone's self-reported checkmarks with measured commands, and
**three of the eight flipped.** That is the second time a gate has overturned a self-report in
this project's history, and it is why the operating loop now says measured judgment outranks
the implementer's ✅ — a rule supported by these repeated discrepancies.

The same gate taught the most expensive lesson of the milestone — the reason this section's
title says *refused to promise*. The gate went back three times in one week, and what kept
failing was not code but **the shape of one criterion**: a sentence of the form "no bypass
exists." A universal over an infinite input space has no fixed target — no implementation can
satisfy it, and one new spelling refutes it forever — so each fix left the criterion open to another
counterexample, with no agreed stopping point. The rule that week produced is now a standing
review criterion of this repository: an acceptance criterion is either a universal over *code
paths* or an *enumerated finite list*, nothing else, and outside the list is a declared limit
rather than a shortfall. Every claim in this post is written under that rule.

The gate also clarified the shell axis's contract. Round 4 of the journal had found calls that
reached history with no record — indirect execution the shell scanner could not see. The fix
that shipped is not a block: it is a **recorded refusal to judge**. Since the backstop landed,
513 `skipped shell-unjudgeable` rows (07-27 through 07-29) name calls that used to masquerade
as `passed`. The contract of the shell axis is now explicit: predicting a shell target from
text is undecidable, so the invariant this axis holds is that *no call passes unrecorded*. A
new spelling landing in `skipped` is the declared limit doing its job; a pass with no row is
the defect class. The distribution backs the design: 78% of all real blocks (640 of 825) come
from the shell axis, while the tool axis — rebuilt on proven `fileChange` evidence — has
produced zero bypass tickets since. In this record, stronger evidence corresponded to fewer defects;
more work on textual prediction
had not produced the same result.

## Solved-problem log

**We believed** the `bypassed` ratio measured valve usage → **what happened**: it measured the
armed window, and three journal rounds built conclusions on it → **what we changed**: the
valve moved behind the verdict so the event *is* the usage, and the journal now writes the
denominator next to every ratio — a rule promoted into the repository's standing review
criteria, where a number without its domain is void.

**We believed** unrecorded indirect execution needed a stronger blocker → **what happened**:
the target of a shell command is not computable from its text, and every stronger textual
predictor invited the next spelling → **what we changed**: the axis's contract became the
record itself — `skipped`, never silent — and new spellings are triaged by one observation:
a row means a declared limit, no row means a defect.
