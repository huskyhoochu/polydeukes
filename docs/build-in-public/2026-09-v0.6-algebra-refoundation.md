# Building Polydeukes in Public #6 — One engine, seven relations, and the promise we could not keep as written

**English** · [한국어](./2026-09-v0.6-algebra-refoundation.ko.md)

> *v0.6.0 · every discipline is now one declaration judged by one engine: two primitives,
> seven relations, witness lists instead of booleans, a closed catalogue of eighteen
> mechanism names. The four predicate families are gone — deleted, not demoted. Post #5
> promised an equivalence count and round two of advise consumption; this post reports why
> the first promise changed shape, and that the second one fired its falsification clause.*

Post #5 closed with two debts. Report the equivalence regression — the whole pre-algebra test
corpus passing against compiled declarations — as a count. And report advise consumption a
second time; if it stayed ignore-dominant, put the delivery channel on trial in public.
v0.6.0 closed on 2026-09-05 with twenty-two tickets. Both debts are paid below, one of
them not in the currency promised.

## What shipped: a judgment is `relate ∘ extract`

A discipline entry used to be one of four predicate keys — `forbid`, `immutable`,
`forbidCommand`, `requirePrecedent` — each with its own code path in the judge. It is now a
`declare` block: a **scope** (which world the declaration admits), **sources** (what it reads
beyond the change — another file, the spawn sidecar, the session transcript), a **supply**
policy for what an absent source means, an **extract** pipeline that turns sources into
keyed item lists, and **relate** entries that compare those lists.

The relation position is closed to seven names: `empty` · `nonEmpty` · `equal` · `subset` ·
`implies` · `ordered` · `unchanged`. Two are primitive (`empty`, `subset`); the other five are
expansions the engine performs internally, and the gate re-verified the four equivalence
laws by exhaustive comparison against a set-theoretic reference over a generated finite
universe. Post #5 said eight. The eighth, `Within`, was the one relation whose boundary was a
constant written in the declaration, and the rule "constants are the extractor's business"
had no other exception — so it went, and its single consumer (the witness valve's TTL) folded
into `nonEmpty` over a filtered extraction.

A relation does not return a boolean. It returns the **witness list** — the items that break
it, in the order the extraction supplied them — and the two surfaces (the session hook and
the commit check) agree on a verdict because neither sorts or deduplicates that list. The
gate proved this the only way it can be proved: the same violation, pushed through both
surfaces, left two telemetry rows whose witness JSON is character-identical.

Every mechanism name is in a closed catalogue of eighteen, and each name locks a shape — the
axes it may read and the relations it may use. A declaration that calls itself `pairing` but
relates `empty` over the change axis is refused at config load with a message that says
which shape the name expects. The negative probes in the gate — an unregistered name, a
registered name with the wrong shape, a relation outside the seven, each of the four retired
keys — all exit 2 with the offending token and the allowed list in the message.

## The promise that changed shape

Post #5 promised the families would be "demoted to sugar that compiles onto one engine" and
that the pre-algebra tests would pass against the compiled declarations, reported as a count.
That is not what happened, and the honest number is not a pass count.

On 2026-09-05 the owner reversed the sugar plan: the four families were **deleted**. The
predicate keys are refused by the schema, the family code is zero lines, and the fourteen
test files that exercised the families were removed rather than ported — the roadmap's phrase
is "zero ports: the promises the family code kept disappear with the code." The reasoning is
the one this project keeps arriving at: sugar that survives is a second grammar, and every
family-specific branch was exactly the implicit mechanism the refoundation exists to remove.

So the count we owe is this. Sixteen root-config entries that were written in the old keys
are now declarations (seven from the change-axis families, nine from the command and history
families), plus eight declarations born in this milestone — twenty-four judged entries and one
draft, and every one of them has left live telemetry rows. The regression suite that stands
in for the deleted corpus is 2,491 tests across five packages, green, plus the gate's live
probes. It is a different proof than the one promised. We are saying so here rather than
letting the number pass for the other one.

## Round two: the falsification clause fired

**Advise consumption: 107/266 = 40.2%.** Same definition as post #5 — an `advised` row whose
(label, subject) is re-observed as `passed` later in the same run. Up from 9.9%, and still
short of half, so this is the second consecutive round of ignore-dominance. The roadmap's
standing instruction for that case is explicit: judge the delivery channel defective before
reconsidering the default posture. We are doing what it says.

The evidence for *channel*, not *posture*, is the split. The three read-before-editing
disciplines — the ones whose advisory asks for an action outside the edit, a Read of one
recorded document — consumed 0 of 123 advisories. Every other family together consumed 107 of
143. DIAG-02 measured last release that the hook's allow-decision `reason` never reaches the
model; two rounds of exactly zero on the one family whose advice cannot be satisfied by
accident is what that measurement predicts. The 75% elsewhere is mostly the approximation
showing its seams — a later edit of the same file that adds no offending line counts as
consumption — so it is evidence of re-observation, not of delivery. The next ticket is a
measured answer to "which channel does an advisory actually reach the model through", with
those three disciplines as its domain. Block does not come back on this evidence.

The other gate indicator held: of 304 natural blocks, 284 were the judging chain protecting
itself and 18 were the two disciplines that explicitly opted into blocking. The gate also
counted, for the first time, what self-protection costs an operator: on the audit day, a
run of read-only commands that mentioned a protected path inside a `$(...)` were refused as
conservative mentions. By the axis's declared contract those are true positives; by the
operator's intent they protected nothing. Both readings are in the journal.

## The gate audited its own grading sheet, again

Three gates in a row, the defects were in the paperwork. The adversarial seat re-read the
twelve exit criteria and found nine sentences to correct: numbers carried from a
decomposition note rather than the landed ticket (fifteen rewritten entries; it was sixteen),
a count of "four property tests" over a file with five exhaustive checks and no property-test
library, a criterion demanding "the same verdict on both surfaces" for a family whose source
one surface structurally cannot carry, and a criterion pointing at a declaration that is not
in the live config. Code blockers found by re-running everything: zero. The corrected
criteria, with their declared limits written next to them, are what the history now carries.

## Release footnote

This one had drama. The release-please port had failed on every push since the day after
v0.5.0 — the repository had been made private, and Forgejo 16 recomputes the actions bot's
permission from repository visibility when *creating* a pull request while granting it write
access for everything else, so the version bump pushed and the PR creation returned 404
forty times. The Forgejo instance is reachable only over the tailnet, so making the
repository public changed nothing about who can read it and fixed the chain. Two more
findings rode along: CI had been red since 2026-09-02 because a permission-refusal test
cannot refuse root, and every CHANGELOG link since the move pointed at a GitHub repository
that does not exist (the port composes host/owner/repo with the Forgejo owner). Release
`v0.6.0` was cut at `c55adc8` from PR #98, after a first release PR had to be closed for a
stale base.
